# 2013 World Book: i386 to arm64 static translation

The shipped app (`2013 World Book.app`, MacKiev, 17.0.0) and its 12 private
frameworks are **i386 only** (plus PowerPC in some frameworks), Objective-C 1
ABI, linked against QuickTime, QTKit, 32-bit Carbon and libstdc++. None of
that runs on current macOS. The Mavis Beacon port's translator (x86_64 → C)
is the starting point; 32-bit code needs more than a new instruction decoder.

## Inputs

- `tools/unarch` + `tools/unzp.py` extract the installer payload
  (`Archive.zp`, MacKiev InstallerMaker "YA" format) into `game/`.
  A stored file can itself be zlib data (`maps_tree.zplst`, World Book's
  "zdat" format: zlib stream, length, `zdat`), which inflates as well; a
  segment is only taken as compressed when nothing but its 9-byte trailer
  follows the stream. The Atlas's map list is that file.
- `analysis/<image>-i386`: thin i386 slices. Symbols are not stripped
  (about 13 000 named functions), so no decompiler pass is needed for names.

## Guest memory

Translated code keeps the original 32-bit semantics: registers and pointers
are 32-bit, and memory is a 4 GB **guest window** reserved at host address
`G`; guest address `p` is host address `G + p`.

    0x00000000  unmapped (null page)
    0x00001000  main executable at its own address
    0x01600000  prebound frameworks at their own addresses
    0x10000000  frameworks linked at 0, rebased here (local relocations)
    0x20000000  guest heap (malloc family), stacks, handle cells
    0xc0000000  frameworks prebound up here (SMKSpeechSynthesis, SMKFoundation, SMKAppKit)

C strings and byte buffers inside the window are usable by native code as
`G + p`. Host buffers handed to the guest (`-[NSData bytes]`, `UTF8String`)
are mapped into the window with `mach_vm_remap` (shared pages, so writes go
both ways) or copied when they are short-lived strings.

## Objects

- **Handles.** The guest sees every object as a 32-bit handle `h` with the
  host pointer at `G + h - 8` and a guest `isa` at `G + h`. Native objects get
  a 12-byte cell when first seen (hash map host → handle).
- **Instances of translated classes** have an i386-layout shadow block in the
  window (instance size from the Objective-C 1 class); the handle is the
  shadow's address, so translated code reads and writes its ivars at their
  original offsets. The host object holds the handle in a hidden ivar; a
  synthesized `-dealloc` frees the shadow.
- **Classes** from the `__OBJC` segment (modules, classes, categories,
  protocols, selector references) are registered with the modern runtime
  (`objc_allocateClassPair`); their methods' IMPs are closures that convert
  host arguments to guest ones per the original type encodings.
- **Selectors** are guest addresses of uniqued C strings; a table maps them
  to host `SEL`s.

## Calls across the boundary

Guest → native (C functions from SDK prototypes, Objective-C messages from
the host method's type encoding plus header knowledge):

- `id`/`Class` handle ↔ pointer; `SEL` guest ↔ host.
- `CGFloat` float ↔ double, `NSInteger`/`NSUInteger`/`long` 32 ↔ 64 bit;
  host encodings don't tell `CGFloat` from `double` or `NSInteger` from
  `long long`, so a table built from the SDK headers (clang AST) names the
  narrowed parameters per selector and function.
- Structs (`NSRect`, `NSRange`, `CGAffineTransform`, ...) field by field.
- Pointers to such types (`NSError **`, `CGFloat *`, `NSRect *`): host
  temporary, copy in, call, copy out. Byte pointers pass as `G + p`.
- Variadic: printf/NSString formats drive the conversion; nil-terminated
  object lists convert each entry.
- Special cases: fast enumeration (host state kept per guest state block),
  `-[NSData bytes]`-style returns (remapped), function pointers (libffi
  closures into translated code).

- `NSTextAlignment` is numbered differently on arm64 (center 1, right 2)
  than on i386 and x86_64 (right 1, center 2): the arm64 slice swaps the two
  for `setAlignment:`, `alignment` and their kin.
- The NSMapTable / NSHashTable C functions run on guest words in
  `maptable.m`, enumeration included; a call left to Foundation would hand it
  the runtime's own table object.

Native → guest: the reverse, driven by the original method's type encoding.

## Instructions

i386 code generated by GCC 4.x: SSE for float maths, x87 only for return
values in `st0` (`fld`/`fstp`) and a few conversions; PIC via
`__i686.get_pc_thunk.*` / `call next; pop`; imports through `__IMPORT,
__jump_table` (5-byte `hlt` stubs) and `__IMPORT,__pointers`. Objective-C 1
exceptions are setjmp/longjmp based (`objc_exception_try_enter` + `_setjmp`).

## Missing system APIs

About 110 QuickTime/QuickDraw (Movie, GWorld, GraphicsImporter,
SoundConverter, atom containers, time bases), QTKit `QTMovie`,
`NSMovie(View)`, a few private CGS calls, `FSp*`/`PBGetCatInfoSync`, libgcc
64-bit arithmetic helpers, 12 libstdc++ symbols. These get shims in the
runtime (QuickTime over AVFoundation/CoreGraphics).

## Universal 2

The translated C does not depend on the host architecture, so every app is
compiled for arm64 and x86_64 and the two are merged with `lipo`
(`xlate/arch.sh`). The one difference the runtime handles: a `%Lf` in a
printf-style format is passed as `long double`, which is the x87 type on
x86_64 and `double` on arm64.

## Home screen

- `NSGraphicsContext -graphicsPort` is declared `void *`, but it is a
  `CGContextRef`: overridden by SMKGLKit's `GLBitmapGraphicsContext`, its
  result has to cross as an object handle, not as a pointer into the guest
  window, or AppKit draws into nothing (`sdk_fixes` in `objc1.m`). The icon
  titles and the media frames are drawn through it into OpenGL textures.
- The home screen is a window the size of a layout less 22 points (2013's
  menu bar). `-[LayoutController loadBestLayoutForScreen:]` picks the largest
  layout that fits `-[NSScreen frame]`; while it does, the screen reports its
  visible area plus 22 points, and the window is then kept inside the visible
  area, so today's taller menu bar and the Dock do not cut it off
  (`appkit.m`).
- On the screen with the menu bar (and with OpenGL) the window has a title
  bar drawn over the layout's top 22 points, which the artwork leaves for it.
  Today's title bar is taller, so it is made transparent over the layout:
  nothing is covered.

## Bundles the apps load

World Book's eight preference panes and both apps' dictionary searchers are
i386 bundles loaded with `NSBundle`. They are translated with the app that
loads them (`xlate/images.txt`; `xlate/app.sh` picks up `Contents/PlugIns`),
under their path in the bundle as install name. Their classes are registered
at launch, so `-[NSBundle load]` of such a bundle only says yes, and
`-principalClass` / `-classNamed:` answer with the translated classes;
`+bundleForClass:` gives the bundle a class came from, for its resources. A
class defined both by the app and a pane (`WBDTextColoringPreviewView`) is
kept once, the first, as dyld did.

The original i386 binaries of these bundles and of the private frameworks
are never loaded, but the files stay: `NSBundle` gives no `executablePath`
for a bundle without one, and that path is how the runtime knows a
translated bundle. `xlate/stub_i386.sh` (run by `mkapp.sh` and `app.sh`)
replaces each with an empty Universal 2 dylib or bundle (frameworks keep
their install names), so every Mach-O file in the apps is Universal 2.

## Old habits

- An NSOpenGLView of an app linked against today's SDK gets a Retina surface
  in pixels; the 2013 views set their viewports from `-bounds` in points and
  would draw a small copy in the corner on a 2x display. They are made with
  `wantsBestResolutionOpenGLSurface` off.

- An image made flipped with `-setFlipped:YES` and drawn into with
  `-lockFocus` (Just Looking's text cards, kept as TIFF) stores its drawing
  upside down today; it is drawn into with `-lockFocusFlipped:YES` instead.

- `performSelector:withObject:` is often handed an integer in disguise (the
  dictionary's index arrays pass an entry number, nibs a BOOL). Calls of a
  translated method pass the guest's words through unchanged; a host method
  gets them converted by its own signature, not as objects.
- A few nibs are typedstream nibs from before keyed archiving. Their
  separator lines are boxes a couple of points tall with the default title
  ("Box") still set, which older AppKit clipped away; views no longer clip to
  their bounds (macOS 14), so such boxes lose a title they cannot show.
  Borderless boxes that only group views keep Interface Builder's placeholder
  title ("Title", "Box") too, which AppKit of the time did not show (the
  Distance Calculator's location panels); the placeholder is emptied, so the
  content stays where the nib put it.

## Help

Help Viewer is gone from macOS 27: `com.apple.helpviewer` is now Tips, which
opens the old HTML help books blank. Where Help Viewer is missing, the
runtime answers Apple Help itself (`AHRegisterHelpBook`, `AHGotoPage`,
`AHLookupAnchor`, `-[NSApplication showHelp:]`,
`-[NSHelpManager openHelpAnchor:inBook:]`): a book is found by its
`CFBundleHelpBookName` in the registered bundles, and the page (or the page
holding the anchor, or the book's table of contents) opens in the default
browser. What's New? is such a call and nothing else. `XL_HELP_BROWSER=0/1`
forces either way; `XL_HELP_DRYRUN=1` logs the page instead of opening it.

## Data the guest fills in

`-mutableBytes` of a short buffer gives the guest a copy in its heap (see
`spec_bytes`); the guest's writes used to reach the real buffer only at the
next `-bytes`. A mutable data object is now brought up to date whenever it
next goes to host code, as a receiver or an argument. Surf The Ages
uncompresses each page into such a buffer and hands it straight to WebKit,
which got zeros: a blank page.

## Surf The Ages

Its pages come from an `NSURLProtocol` (`stm://SurfTheAges/...`) whose
responses carry no MIME type. Old WebKit guessed one from the extension;
today's stops the load ("Frame load interrupted"). A response made without a
type, for a URL outside the standard schemes, gets its extension's type.

## Plist values for BOOL instance variables

Layout plists give BOOLs as strings ("YES"), and `NSString` has no
`-charValue`: those keys raised and were skipped, leaving
`useTextureRectangle` and the like at their defaults, and the home screen's
showcase then textured some photos wrongly (a photo repeated across its card,
cards seeming to overlap). Strings now set them through `-boolValue`.

## Home screen photos

The OpenGL home screen tells the media provider what textures to make for
the photos (rectangle ones, which do not repeat) in `-onceInit`, which
`-[GLView drawRect:]` runs at the view's first draw. `-[LayoutController
showHomeScreen:]` shows the window and then starts the provider's
preloading thread. In 2013 `-showWindow:` had drawn the window by the time
it returned; today the first draw waits for the next display pass, so the
thread made its first photo with no flags at all: a power-of-two texture
that repeats, and the strip showed that photo again over the cards beside
it (a translucent ghost of one card's photo on another). Preloading now
starts once the view has drawn (`appkit.m`): at once where `-display` still
draws it, else on a later turn of the run loop.

## Home screen videos

Some cards of the home screen's strip are movies (`MOVIES/vd00NNNN.mov`,
H.264). SMKGLKit's `GLMovieEffect` plays them as the Mac OS X 10.4 QuickTime
API: `-[NSMovie QTMovie]` gives the Movie, `GetMovieIndTrackType`,
`GetTrackMedia` and `GetMediaSample` read its video media, and an ICM
decompression sequence (`DecompressSequenceBeginS`, `...FrameWhen`) decodes
each sample into a GWorld over the card's texture bitmap. `qtimport.m` keeps a
Movie as an `XLMovie` on an `AVAsset` and its tracks as `XLTrack`s (a Track and
its Media are one handle). The "sample" `GetMediaSample` returns is a 16-byte
token (movie handle, media time) and the decompress call turns it into the
frame an `AVAssetReader` delivers for that time, copied as ARGB to the GWorld's
top left corner (the codec drew at the natural size with no matrix). The reader
runs forward with one frame of look-ahead and restarts when the time goes back
(the loop). `-QTMovie` returns the `XLMovie` as `void *`, so that the bridge
makes the handle (a plain integer return was made a second handle).

## Home screen viewport

`-[GLView drawRect:]` depends on the context's viewport, which `-reshape` and
`-update` set from the view's bounds. After the Media Center was shown and left,
the viewport was 412x304 while the view stayed 1440x878 (something else
renders on the shared context at that size and leaves it): the layout drew in
the corner, beside the previous full-size frame. `appkit.m` sets the viewport
from the view's size in pixels at the start of every `drawRect:`.

## Toolbar pop-up menus and the sticky note

- HSToolbarItem's viewer posed as AppKit's private `NSToolbarItemViewer` to
  show an item's pop-up menu when pressed (Theme's list of skins); posing is
  gone, so pressing Theme did nothing. `-[NSToolbarItemViewer mouseDown:]`
  shows the menu of an item whose `alwaysShowsPopupMenu` is set, below the
  item, and runs the original for every other item (`appkit.m`).
- `StickyNoteView.nib` holds the note's text views as `NSTextTemplate`, which
  10.2's Interface Builder archived `NSTextView` as and current AppKit no longer
  has ("class not loaded"): a new note got its icon in the article but no
  window. `+[NSBundle loadNibNamed:owner:]` builds that nib in code (a
  `WBStickyNoteView` of 448x313, a one-line title on top, the content below,
  the outlets set, then `-awakeFromNib`). Other nibs load as before.
